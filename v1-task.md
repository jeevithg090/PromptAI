# v1-task.md — PromptForge V1 Overhaul Ledger

> **Prime directive (the redemption rule):** every task below is DONE only when it is **visible and working in the running website** (`web/` on :3000 against `backend/` on :3001). Backend-only code that "sits and rots in files" is a FAILURE state. Every task's acceptance criteria therefore end with a browser-verifiable check. Verify in the browser (screenshot or read_page) before checking a box.
>
> **Standing rules** (inherited from task.md §0): one-way dependency flow `handlers → services → agents → utils/types`; config over code; never log prompt content; safety fails closed; every new service/route gets tests; typecheck + full jest must stay green after every phase; strings via `web/src/lib/strings.ts` (no hardcoded JSX English); DB-degraded mode must keep working (local dev has no reachable Postgres for some tables — services degrade gracefully, they never 500).
>
> **Design rule (V1.9 applies globally):** clean editorial UI — ink/paper neutrals, ONE accent color (emerald-600), generous whitespace, no gradients of any kind (explicitly: no purple), no glassmorphism. Every new page/component uses the shared primitives from V1.9.

### [x] V2.1 — Prompt Debugger — **COMPLETE (2026-07-12):** POST /debug (PromptDebugService, node-level faults w/ quoted evidence + patched nodes), /debug page (3 inputs, severity-colored fault cards, patched prompt opens inline in NodeEditor via lib/nodes.toDesignedResponse). API-verified: weak ocean-poem prompt → 3 faults (missing form/tone/structure) + patched nodes.
The single most common real-world loop: you ran a prompt, the output was wrong, now what? Paste **your prompt + the bad output + what you expected**. `POST /debug` → `PromptDebugService` (large tier, new step `debug`): parses the prompt into nodes (reuse PromptImportAgent), then produces `{ diagnosis: [{ node_type|'(missing)', fault, evidence (quote from the bad output), severity }], patched_nodes[], patch_summary }`. Web: `/debug` page — three inputs (prompt, actual output, expected), results as a fault table (severity-colored) + before/after diff of the patched prompt + "Open patched in editor" + TokenMeter. Tests: service happy/malformed/retry, route mounted. **Accept (browser):** paste a weak prompt + wrong output → get node-level faults with quoted evidence and a patched prompt that opens in the editor.

### [x] V2.2 — Reverse Prompt — **COMPLETE (2026-07-12):** POST /reverse (ReversePromptService infers task+nodes, rationales trace to quoted fragments, real Critic scoring), /reverse page (output textarea + platform → scored NodeEditor + inference banner). API-verified: ceramic-mug output → 76 scored prompt, nodes trace to fragments.
"I saw a great output — what prompt produces this?" Paste an example output (copy, article, code, image *description*). `POST /reverse` → `ReversePromptService` (large): infers task type + a full node set that would plausibly generate it for the chosen platform, each node with rationale "inferred from: <quoted fragment>". Web: `/reverse` page — output textarea + platform select → result in NodeEditor with score (run Critic), plus honest banner "inference, not extraction — tune to taste". **Accept (browser):** paste a sample product description → get an editable scored prompt whose subject/style nodes visibly trace to fragments of the sample.
